Generated by `python -m evaluation.run_backtest --days 180`.
Raw metrics: `data/backtest_metrics.json` · dataset: `data/labelled_signals.csv`

## Setup

| | |
|---|---|
| Strategy | `ema_rsi_trend_v1` (EMA 20/50 cross + RSI 14 window + market structure) |
| Symbols | BTC, ETH, BNB, XRP, SOL (USDT-M perp symbols) |
| Timeframe | 15m |
| Period | 2026-03-09 → 2026-09-04 (180 days) |
| Candles evaluated | 17,160 per symbol |
| **History vendor** | **KuCoin spot** — *not* the execution venue (see below) |
| Costs | 0.06% taker fee + 0.05% slippage, per side |
| Risk | 1% per trade, 3% daily cap, 2% per correlated cluster, max 4 positions |
| Stop / target | 1.5 × ATR(14) stop, 2R target |

### Data provenance

KuCoin **spot** is not Toobit **perpetual futures**. Different books,
different participants, and perps carry funding. These numbers measure the
*strategy*, not the fills the target venue would have produced. Toobit
ignores `since` and caps history at ~1000 candles (≈10 days on 15m), and
Binance is unreachable from this network, so a separate vendor was the only
way to get 180 days. See README OD-5.

## Why: the arithmetic

A 2:1 reward-to-risk setup breaks even at a **33.3%** win rate.
This strategy produced **34.05%** — a gross edge of about **+0.02 R**.

Costs per round trip are 2 × (0.06% + 0.05%) = **0.22%** of notional.
The stop sits 1.5 × ATR away, which on these symbols is **0.30–0.45%**:

| Symbol | Median ATR% | Stop distance | Round-trip cost | Cost as fraction of 1R |
|---|---|---|---|---|
| BTC | 0.2096% | 0.3145% | 0.22% | 0.70 R |
| ETH | 0.2932% | 0.4398% | 0.22% | 0.50 R |
| BNB | 0.2003% | 0.3005% | 0.22% | 0.73 R |
| XRP | 0.2763% | 0.4144% | 0.22% | 0.53 R |
| SOL | 0.2999% | 0.4499% | 0.22% | 0.49 R |

So roughly **0.6 R of cost** is subtracted from a **+0.02 R** gross edge.
−0.566 R observed is what that predicts.

## Sensitivity

Same data, same strategy, varying only costs and stop width:

| Scenario | Trades | Win rate | Expectancy | Return |
|---|---|---|---|---|
| Legacy spot-spread costs (0.10% fee / 0.25% slip) | 75 | 10.7% | −2.22 R | −26.9% |
| **Measured perp costs (0.06% / 0.05%)** | **75** | **32.0%** | **−0.73 R** | **−12.5%** |
| Measured costs, 3.0× ATR stop | 67 | 32.8% | −0.36 R | −11.2% |
| Measured costs, 5.0× ATR stop | 52 | 30.8% | −0.29 R | −11.0% |
| **Zero cost (impossible upper bound)** | 75 | 32.0% | **−0.04 R** | −4.9% |

*(Sensitivity rows are the 60-day window; the headline table is 180 days.
Raw: `data/sensitivity.csv`.)*

The last row is the one that settles it. **At literally zero transaction
cost the strategy is still slightly negative.** Costs made the result look
catastrophic; they were not hiding a profitable system underneath.

### The cost model was wrong, and is now measured

The first version of this backtest used 0.25% slippage per side, derived from
CoinGecko's whole-exchange average *spot* spreads (LBank ~0.44%, Toobit
~0.54%). Against the real target market that was wrong by one to two orders
of magnitude. Measured on Toobit USDT-M perps by walking the live order book
for a 10,000 USDT fill (2026-09-04):

| Symbol | Top-of-book spread | Slippage on a 10k fill |
|---|---|---|
| BTC | 0.00075% | 0.00038% |
| ETH | 0.01626% | 0.00813% |
| BNB | 0.00975% | 0.00487% |
| XRP | 0.03526% | 0.01763% |
| SOL | 0.01960% | 0.00980% |

The setting is now 0.05% per side — about **3× the worst measured value**, as
a buffer for fast markets where books thin out and stops fill worse than a
calm-market snapshot suggests. The 0.06% taker fee is an **assumption**
(Toobit does not publish fees through ccxt) — README OD-8.

## What was NOT done

**The strategy was not tuned to make these numbers look better.**

Widening the stop improves expectancy in the table above, and picking the
best-scoring row would be curve-fitting to 180 days of a single market
regime — precisely the failure mode this project's ground rules call out. The
cost model was corrected because it was *factually wrong* against measured
venue data. The strategy parameters were left alone because there is no
honest basis for changing them yet.

Nothing here is evidence that a 3× or 5× ATR stop is better. It is evidence
that expectancy is less negative at wider stops on this sample, which is what
you would expect when a fixed cost is amortised over a larger R.

## Leakage controls

Three, all enforced by test rather than by comment:

1. **The strategy only ever receives `frame.iloc[:i+1]`** — the candles up to
   and including the decision candle. `test_strategy_only_ever_sees_the_prefix`
   captures every window handed to the strategy and asserts the lengths are
   exactly `121, 122, … n`.

2. **Indicators are causal.** The engine precomputes them once for speed, which
   is only valid if every indicator is strictly backward-looking.
   `test_indicators_are_causal_so_precompute_equals_per_prefix` recomputes on
   truncated prefixes and asserts the values are unchanged. If anyone adds a
   centred or forward-filled indicator, that test fails.

3. **A trade opened on the signal candle fills at that candle's close and can
   only be resolved by later candles.** The bar that triggers a trade can never
   also pay it out.

Plus one at the modelling stage: the confidence calibrator splits
**temporally**, never randomly (`test_split_is_ordered_in_time_not_random`).

---

## Interpretation

Two honest caveats on the negative result:

- **One regime.** 180 days is a single market period. The sample says this
  strategy did not work over these six months; it is not a proof about all
  conditions.
- **185 trades is a small sample.** The gap between 34.05% and the 33.3%
  breakeven is far inside the noise band at this size. The correct reading is
  "no detectable edge", not "a precisely measured small negative edge".

Neither caveat points the other way. Nothing in this data supports moving
toward live capital, and the decision about what to change is recorded as
README **OD-10** rather than made unilaterally.
